# 开发说明

给要改这个项目的人（包括我自己）看的：架构、构建/测试命令、以及踩过的坑。

## 架构

```
课表.pdf
  └─ src/timetable/parser.py   用 PyMuPDF 读文字块坐标 → 结构化 Record/Segment
       └─ src/timetable/ics.py Config + build_ics() → VEVENT（RRULE + VALARM + EXDATE）
            ├─ holidays.py     法定节假日预设 / 调休 / 外部节假日文件
            ├─ presets.py      作息时间预设
            └─ doctor.py       配置自检：抓「换学期忘改日期/节假日」这类静默错误
  ↑ 界面 gui.py + ui_kit.py（tkinter，自绘圆角控件）
  ↑ cli.py 命令行；main.py 统一入口
  ↑ installer-src/Installer.cs（C# WinForms 安装器，csc.exe 编译，不依赖第三方打包工具）
```

两个关键的解析经验（改 parser 前务必先看）：

1. **先按 x 坐标判定文字属于星期几，再在**每列内部**按 y 分组成行。**
   课表不同格子的字号不同，同一视觉行的 y 会有 ~0.9px 的偏差；
   如果先按 y 全局分组，会把不同列的内容并到一行里，教室/教师全乱。
2. **空白 span 不能丢。** 教室和教师靠空格分隔，丢掉空白后会出现
   「C座5楼某某某」这种把教师并进教室的结果。保留空白 span、折叠连续空白，再按空格切分。

## 构建

```powershell
pip install -r src\requirements.txt pyinstaller

powershell -ExecutionPolicy Bypass -File build_onedir.ps1             # → dist\TimetableToCalendar\
powershell -ExecutionPolicy Bypass -File build_installer.ps1 -Clean   # → dist\TimetableToCalendar-Setup.exe
```

- `build_onedir.ps1`：PyInstaller onedir 构建应用本体（安装包的载荷来源），
  构建后把 `assets\README.md` 复制进去；如果项目根目录有 `sample-timetable.pdf`，
  也会一起复制（这个文件在 `.gitignore` 里，用来带上自己的示例课表）
- `build_installer.ps1`：把应用本体用 7-Zip LZMA2 压到约 1/3，然后把
  「压缩载荷 + `7z-extra\x64\7za.exe` + 8 KB 小卸载器」内嵌进用 `csc.exe` 编译的
  C# 安装器，最后合成一个 exe。`-Clean` 会在打包后删掉中间产物

> 两个 `.ps1` 必须保存为 **UTF-8 带 BOM**，否则 Windows PowerShell 5.1 按 GBK 解析中文
> 会直接语法错误。**有些编辑/替换工具会把 BOM 吃掉**，改完要确认：
> `[System.IO.File]::WriteAllText($p, $t, (New-Object System.Text.UTF8Encoding($true)))`

## 踩过的坑

### tkinter / Pillow

- 属性名不能叫 `self._w`（tkinter 内部保存控件路径）、不能叫 `self._options`
  （`Misc._options()` 内部方法）—— 覆盖后控件会「失联」，报 invalid command name
- 同一个容器里不能混用 `grid` 和 `pack`（`place` 例外）
- **`pack` 顺序决定空间分配**：`expand=True` 的中间区如果先 pack，会把 `side="bottom"`
  的底栏挤成 1×1；空间不够时先 pack 的控件会把后 pack 的挤没
- Canvas 没有抗锯齿，圆角必须用 Pillow 预渲染图片
- **Pillow 画圆角不能直接 `Image.new("RGBA", ..., (0,0,0,0))` 再缩放**：透明区底色是黑，
  LANCZOS 会把黑渗进边缘形成**暗角**。正确做法是「形状覆盖度」走 L 通道当蒙版、
  「颜色」走不透明 RGB 图，两者各自缩放后再合成（`check_corners.py` 是回归检查：
  修复前边缘 RGB 偏差平均 4.44 / 最差 19，修复后 0.00 / 0）
- **圆角底图用 9 宫格**，不要按控件尺寸缓存整图：中心用矩形、边用 1 像素直线、
  4 张圆角贴图缓存复用（`_draw_round()` / `corner_tiles()`），缩放时只挪位置
- `ImageTk.PhotoImage` 绑定在具体 Tk 解释器上，缓存键要带解释器标识
- **`ttk.Treeview` 不会自动压缩列宽**：各列宽度之和超过控件宽度时右边的列直接被裁掉。
  要自己按可用宽度分配列宽（`_fit_columns()`），并处理逐列取整误差；
  实在塞不下才用横向滚动条（`xview` / `xscrollcommand` 是可用的）

### DPI

- 必须用 `SetProcessDpiAwareness(1)`（系统级）。用 `(2)`（逐显示器）实测无效，
  Tk 仍然只看到 96 DPI
- 声明 DPI 感知后所有像素尺寸都要按比例放大，窗口尺寸也不例外
- **截图只能在程序自己进程里做**（`main.py --shot`）：外部工具进程往往不是 DPI 感知的，
  `GetClientRect` 返回逻辑像素而目标按物理像素渲染，截出来是半张错位图。
  另外窗口只要有一部分在屏幕外，抓到的那部分是黑的，会被误判成「没画出来」

### 窗口尺寸与滚动

- **不要用 `minsize` 去保证「内容全部可见」**：那等于把竖直方向锁死
  （实测最小高度 1823 物理像素、屏幕可用 1879，能拖的范围只剩 56 像素）。
  正确做法：最小尺寸给小，内容装不下用滚动条兜住
- **默认尺寸跟屏幕走**：取屏幕宽高各一半（面积约 1/4 屏），再夹到
  [最小尺寸, 屏幕可用范围]；不要写死像素值
- 中间内容区放在 `Canvas` + 内层 Frame：画布宽度决定内层宽度，内层高度取
  `max(可视高度, 内容自然高)` —— 拉高时预览表跟着变高，压矮时内容保持自然高。
  顶栏和底栏不放进画布，永远固定在窗口上
- 滚动条只在需要时 `pack`（`before=` 插到正确位置），**状态不变就不要动**，
  否则 `<Configure>` 与布局互相触发会打转；差几像素时先压缩可伸缩的那一块
- `Canvas.winfo_reqheight()` 不等于内容高度（画布不传递内层的请求尺寸），
  要用内层 Frame 的 `winfo_reqheight()`
- 滚轮绑在顶层窗口上，但要在处理函数里用 `winfo_containing()` 判断指针位置：
  在预览表 / 日志里时不翻页（交给它们自己滚），否则会滚两层

### 安装器 / 卸载器（C#）

- 设了 `AllPaintingInWmPaint | UserPaint` 之后，**OnPaint 要负责画全部内容**，包括背景。
  圆角之外必须显式 `g.Clear(BackColor)`：不清的话那块是未初始化的缓冲（黑），
  GDI+ 抗锯齿会把黑混进圆角边缘 —— 视觉上就是**暗角**
- 控件放在白色卡片上时 `BackColor` 要跟着卡片走，否则清背景会在按钮周围留一圈灰底
- 重写 `SetupForm` 时漏掉了「浏览…」按钮，靠 `--uitest` 打印的控件总数（11 → 12）
  才发现，所以那个报告要保留控件计数
- **覆盖安装时如果旧版本程序还在运行**，7za 覆盖不了那个 exe，会报
  「解压失败，7za.exe 返回 2」。现在 `RunningFrom(dir)` 会先查一遍并给出明确提示。
  注意**要把自己这个进程排除掉** —— 卸载器本身就在安装目录里，不排除的话永远判成
  「正在运行」，卸载直接失效
- **安装位置统一补一层项目名子目录**（`NormalizeDir()`）：用户常只选到 `D:\Tools`
  这种父目录。两个坑：① `"D:\"` 被 `TrimEnd('\')` 成 `"D:"` 后 `Path.Combine` 会得到
  `D:TimetableToCalendar`（盘符相对路径，含义完全不同），要在只剩盘符时补回斜杠；
  ② 规则必须**幂等**，否则重复安装会装成两层。`--pathcheck` 就是这条规则的自检
- **卸载残留文件夹的两个真正原因**（都实测复现过）：
  ① 删除进程的工作目录如果就在被删目录里，`rmdir /s /q` 会失败
  （`The process cannot access the file because it is being used by another process`）；
  从「设置 → 应用」或双击 `Uninstall.exe` 启动时工作目录正是安装目录 —— 而用
  `Start-Process` 从别处启动时工作目录是调用者的目录，**所以这个 bug 在自动化测试里
  看不出来**，必须显式传 `-WorkingDirectory <安装目录>` 才能复现；
  ② 正在运行的卸载器自己占着目录里的 exe。
  最终方案：卸载器把自己复制到 `%TEMP%` 再启动副本删除（原进程立刻退出），
  副本带重试地 `Directory.Delete(dir, true)`，删完再删自己
- 安装时如果父目录是新建的，记 `ParentCreated=1` 到注册表；卸载时把空父目录一并删掉，
  否则用户会看到一个残留的空文件夹

### PowerShell（写构建脚本时）

- `.ps1` 含中文必须 UTF-8 带 BOM；用编辑工具改完要复查（BOM 容易被吃掉）
- 不支持 `<<'EOF'` heredoc；`Start-Process -ArgumentList` 传数组时不会给含空格的路径
  自动加引号；对 `--windowed` 的 exe 用 `&` 调用不会等待，要用 `Start-Process -Wait`
- `Select-Object -First N` 会提前掐断管道，让被截断的命令返回 `[exit code: 1]`（不是失败）
- 测卸载/删除类逻辑时要用 `Start-Process -WorkingDirectory <被测目录>` 复现真实启动环境

## 保持仓库干净

发布到仓库的版本里**不要包含个人课表**（`课表.pdf`、生成的 `.ics`、这些文件的截图），
它们都写在 `.gitignore` 里。要带示例课表时，把它命名为 `sample-timetable.pdf` 放在项目
根目录（同样被忽略），构建时会自动复制进产物。

`docs/` 下的文档是面向使用者的；开发笔记（也就是本文件）可以随时补充新踩的坑。
