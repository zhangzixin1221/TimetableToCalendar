# 课表 PDF → 手机日历（.ics）

把**教务系统导出的《学生课表》PDF**，转成可以直接导入 iPhone / iPad / Mac /
Android 日历的 `.ics` 文件，并自动加上两类提醒：

1. **每节课提前 N 分钟提醒**（默认 20 分钟）
2. **每晚固定时间汇总第二天要上的所有课**（默认 22:00）

还会按**法定节假日**停课（用 iCalendar 的 `EXDATE` 从循环里精确剔除），并处理**调休**
（节假日安排可以**联网按年份自动获取**，也可以自己填）。

内置一套**西北工业大学**的课表版式（开箱即用）；别的学校/别的教务系统靠
「版式」适配 —— 不用改代码，选一个版式或写一份 JSON 配置即可，见
[换学校 / 换教务系统](#换学校--换教务系统版式)。

> Turn a course-timetable PDF (NWPU out of the box, other schools via a pluggable
> *layout*) into an `.ics` calendar with per-class reminders, a nightly
> "tomorrow's classes" summary, Chinese public-holiday handling — online or manual —
> and a one-file Windows installer.

界面是中文的，程序跑起来不需要 Python。

## 下载与安装

到 [Releases](../../releases) 下载 **`TimetableToCalendar-Setup.exe`**（约 28 MB），双击安装。

- 默认装到 `D:\Tools\TimetableToCalendar`（没有 D 盘时用
  `%LOCALAPPDATA%\Programs\TimetableToCalendar`）
- 只写 `HKCU`，**不需要管理员权限**
- 程序文件全是英文路径（`TimetableToCalendar.exe` / `Uninstall.exe`），界面文字是中文
- 卸载：开始菜单或「设置 → 应用」，也可以直接跑安装目录里的 `Uninstall.exe`

> 首次运行会弹 SmartScreen「Windows 已保护你的电脑」——因为没有代码签名。
> 点「更多信息」→「仍要运行」即可。

## 怎么用

双击 `TimetableToCalendar.exe`，然后：

1. 「课表 PDF」选你的课表，「输出 .ics」会自动填好
2. **确认「第 1 周周一」的日期**（最关键的一步，见下文）
3. 点「解析课表」
4. 对着预览表核对一遍（有错的直接双击那一行改）
5. 点「生成 .ics」

快捷键：`F5` 解析、`Ctrl+S` 生成、`Ctrl+O` 选择文件。

### 把 .ics 导进 iPhone

1. **邮件**（最省事）：把 `.ics` 当附件发到自己邮箱 → iPhone 打开邮件 → 点附件 →
   「添加到日历」→「全部添加」
2. **iCloud 网页版**：`icloud.com/calendar` 里找导入入口
3. **AirDrop**（Mac）：隔空投送到 iPhone，用「日历」打开
4. **文件 App**：存进 iCloud Drive，iPhone 上点开 → 共享 → 日历

> 建议先新建一个叫「课表」的日历再导入，以后不想要了删掉这一个日历就干净了。

### 命令行

```powershell
TimetableToCalendar.exe --cli 课表.pdf
TimetableToCalendar.exe --cli 我的课表.xlsx                              # Excel 也能直接当输入
TimetableToCalendar.exe --cli 课表.pdf -o 我的课表.ics --week1 2026-08-31
TimetableToCalendar.exe --cli 课表.pdf --alarm 15 --night 21:30   # 提前 15 分钟 + 每晚 21:30 汇总
TimetableToCalendar.exe --cli 课表.pdf --alarm 0 --night off       # 完全不要提醒
TimetableToCalendar.exe --cli 课表.pdf --merge artifact            # 相连节次合并策略
TimetableToCalendar.exe --cli 课表.pdf --remark-courses            # 备注课程也加为全天日程

# Excel：模板 / 把解析结果导出核对（改完可直接当输入）
TimetableToCalendar.exe --cli --xlsx-template 课表模板.xlsx
TimetableToCalendar.exe --cli 课表.pdf --xlsx-out 核对.xlsx

# 节假日默认联网获取；想落成可手改的文件：
TimetableToCalendar.exe --cli 课表.pdf --save-holidays 节假日.txt
TimetableToCalendar.exe --cli 课表.pdf --holidays-years 2026,2027 --holidays-refresh

# 换学校 / 换教务系统
TimetableToCalendar.exe --cli 课表.pdf --auto-layout               # 自动挑版式
TimetableToCalendar.exe --cli --list-layouts                       # 有哪些内置版式
TimetableToCalendar.exe --cli 课表.pdf --dump-layout               # 看程序眼里的版面结构
TimetableToCalendar.exe --cli --layout-template                    # 导出版式配置模板
```

`--cli -h` 可以看到全部参数。从源码跑就把 `TimetableToCalendar.exe` 换成
`python main.py`。

## 三种输入：PDF / 图片（OCR）/ Excel

程序按文件类型自动分流，**不需要你选**：

| 你的文件 | 走哪条路 | 准确度 |
|---|---|---|
| PDF（有文字层） | 读文字坐标，精确解析 | 最高（推荐） |
| 图片（png/jpg）或扫描件 PDF | **OCR 识别** → 同一套结构解析 | 实测 88%（**必须核对**） |
| `.xlsx` / `.csv` | 直接读单元格 | 100%（不含解析误差） |

**图片 / 扫描件**：直接把课表照片或截图选进来即可。程序会：
1. 自动判断「有没有文字层」——有文字层的 PDF 绝不会走 OCR（那样反而更差）；
2. 逐页识别，把结果解析成课程；
3. **在预览表里把 OCR 出来的行标成淡黄底**、状态栏写「来自图像识别，请核对」；
4. 低置信度的文字单独列出来（「有 1 处文字识别置信度偏低，可能就是错的地方：…」）。

实测数据（拿合成课表渲染成图、有标准答案可对）：

| 场景 | 与坐标解析的一致率 |
|---|---|
| 干净渲染 150dpi | 88%（22/25 条逐字段一致） |
| 带 JPEG 压缩 / 轻微旋转 | 88%（关键字段仍在，细节有损失） |

> 真机拍照会更差（透视、反光、褶皱）。所以流程是：**识别 → 你核对 → 再生成**。
> 核对时最快的做法是「导出结果核对…」存成 Excel，在 Excel 里改完再当输入 —— 那条路 100% 准确。

依赖：本地 OCR 用 RapidOCR + onnxruntime（离线、**不上传你的姓名学号**），安装包因此大约 +50MB。
没装 OCR 依赖时，图片输入会明确提示装什么，其余功能不受影响。

### 文字层也可能是坏的：「假汉字」与 OCR 交叉验证

**有文字层不代表文字是对的。** 实测遇到过两类：

- **假汉字**：网页打印会把常用字写成「康熙部首」区的字符 —— `⻄`(U+2EC4) 不是 `西`，
  `⼯`(U+2F2F) 不是 `工`。看着一模一样，程序按字节比较就全不匹配，一份课表直接
  报「没有找到星期一…星期日表头」。
- **乱码**：字体子集缺失时，提取出来是 `(cid:123)` 之类。

程序的处理分两层：

1. **先归一**（默认就做）：部首字符还原成正常汉字（NFKC + 手工映射），
   且**只在真的遇到这类字符时才动**，普通 PDF 的原文一字不改。
2. **再用 OCR 复核**（文字层可疑时自动触发）：把页面渲染成图、OCR 认一遍，
   与文字层逐处比对。**布局仍信文字层（坐标精确），OCR 只核对"这个字到底是不是这个字"**
   —— 两条通道各用长处。

触发条件：**默认每份课表都复核**（`--crosscheck on`）。三种输入的处理：

| 输入 | 复核 | 原因 |
|---|---|---|
| PDF（有文字层） | ✅ 每次都跑 | 文字层可能"看着对、码位错"，只有像素能作证 |
| 图片 / 扫描件 | ⏭ 跳过并说明 | 本身就是 OCR 认出来的，再认一遍没有意义（结果仍需你核对） |
| Excel / CSV | ⏭ 跳过并说明 | 结构化输入，没有"文字层"这一环，单元格本身就是确定的 |

嫌慢可以换档位：`--crosscheck auto`（仅文字层露出可疑迹象才跑）/ `off`（不跑）。
单页 OCR 约 5~15 秒，一份两页的课表大约多 20~30 秒。

复核结果会这样告诉你（一致性低于阈值时才列）：

```
OCR 复核：比对 139 处文字，其中 136 处能与文字层对上
  ⚠ 有 3 处两边读数不一致，请核对（左=文字层，右=OCR 看到的样子）：
    第1页 文字层='学院：航海学院'  OCR='航海学院'（相似度 57%，OCR 置信度 80%）
```

**默认只报告、不自动改数据**：OCR 也会错（实测渲染图字符召回 88~92%），
自动采纳会把 OCR 的错混进本来正确的数据里。OCR 自己置信度不足（<60%）的读数
不计入"不一致"，只记为"无法判定"——否则会误导你去改本来正确的地方。

实测一致率：健康课表 99.4%（166 处）、假汉字课表 97.8%（139 处）。

## Excel / CSV：门槛最低、结果最确定的入口

PDF 解析再准也有猜的成分（版面还原、教室教师切分、时刻反查）。**Excel 没有这些问题**
——单元格就是单元格。所以它既是"不想折腾 PDF"时的正门，也是"解析结果要改"时的退路。

三个用法：

1. **从零填**：`--xlsx-template 课表模板.xlsx`（界面「空模板…」）导出模板，一行一条课：
   课程名称 / 课程代码 / 星期 / 节次 / 周次 / 教师 / 上课地点。填好直接当输入。
2. **核对修改**（推荐）：`--xlsx-out 核对.xlsx`（界面「导出结果核对…」）把**解析结果**
   导出成同一格式的 Excel → 在 Excel 里改错行 → 把这个文件当输入重新生成。
   解析错的地方改一次就永久正确，不必和 PDF 解析较劲。
3. **CSV**：Excel 里「另存为 CSV」也行（UTF-8 与 GBK 都认）。

几个约定：

- **列名不用一字不差**：`课程/课程名/课程名称/科目`、`教室/地点/上课地点`、
  `教师/老师/任课教师`、`星期/周几`、`节次/上课节次`、`周次/起止周` 都认。
  表头也不必在第 1 行（前面可以有标题行），程序会在前 10 行里找。
- **星期**写「星期一」「周一」或 `1`–`7`；**节次**写 `1-2`、`1-2节`、`第1-2节` 或 `3`；
  **周次**写 `1-16`、`2-16(双)`、`1,3,5`、`第3周`。
- **一门课多段就写多行**（不同周次/教室/教师各一行），程序会自动合并同一格的同名课。
- 出错会**指到具体位置**，例如「第 5 行「线性代数」的节次认不出来（'一二'），已跳过；
  例：1-2 或 3」，而不是笼统报失败。
- Excel 里填的是**第几周**，不是日期；具体哪天还要在程序里填「第 1 周周一」。

> 注意：Excel 路径不读学期、姓名、学号这些元信息（它们只用于日历名），
> 日历名会退化成「课表」。用 `--name` 或界面上的日历名自行指定即可。

## 换学校 / 换教务系统（版式）

「版式（layout）」= 一所学校课表 PDF 的**排版约定**：星期表头叫什么、周次写成
`(1~16周)` 还是 `1-16周`、节次怎么标、教室和教师谁在前、这门校作息几点打铃。
这些全部抽成了配置，不再写死在代码里。

内置三种版式：

| id | 适用 | 说明 |
|---|---|---|
| `nwpu`（默认） | 西工大教务《学生课表》 | 七列星期 + 格子里「标题行 + `(N周)(N-M节) 教室 教师`」，自带长安/友谊校区作息 |
| `inline-grid` | 网格式，但每行自带课程名 | 例如一行写成 `高等数学 1-16周 1-2节 张伟 教三-101` |
| `flat-table` | 平面表，一行一条课 | 有 `课程名称/教师/星期/节次/周次/上课地点` 这类列名的列表式导出（正方、强智常见） |

### 三步适配你自己的学校

1. **先让程序把 PDF 摊开给你看**：`--dump-layout`（界面里是「看结构」按钮）。
   输出会逐行标明每行被判成*标题行 / 详情行 / 说明行 / 续行*，以及教室教师被切成了什么：

   ```
   y=  90.1  详情行    (1~16周)(1-2节) 教西D-101 陈明远
            周次 1~16  节次 1-2  →  教室='教西D-101' 教师='陈明远'  剩余=''
   ```

2. **试内置版式**：`--auto-layout` 会挨个版式试解析并打印各自成绩（课程条数、读出
   教室的条数、时间冲突数），挑一个最好的。也可以直接 `--layout flat-table` 指定。

3. **内置的都不像，就写一份配置**：`--layout-template` 导出 `my-school-layout.json`
   模板，照着第 1 步的输出改三条正则（`weeks_re` / `period_re` / `title_re`，要写
   `(?P<a>…)` 这种具名分组），然后 `--layout my-school-layout.json` 用（界面里点
   「载入配置…」）。字段名**写错会当场报错**，不会悄悄退回默认值骗你生成一份错日历。

版式配置里还能带：`period_presets`（贵校作息表，这样下拉框就不再是西工大的节次）、
`room_teacher`（教室/教师的切法：教师在前还是在末、是否用「教师：/教室：」标签）、
`meta_labels`（`姓名：`/`学号：` 这些标签在你学校叫什么）、`semester_hint`（学期起点，
换版式时拿来预填「第 1 周周一」）。

> **诚实说明**：`nwpu` 是按真实导出格式反复验证过的；`inline-grid` / `flat-table`
> 是按常见教务导出**格式**实现并用合成 PDF 验证的，没有拿某一所具体学校的真件验过。
> 你的学校解析不对时，`--dump-layout` 是唯一可靠的诊断入口 —— 欢迎把改好的 JSON 提上来。

## 必须自己确认的几个点

程序只能从 PDF 里读到「第几周」，**读不到绝对日期**。上下课时间则优先用 PDF 上印的
时刻，PDF 没印才用作息表推。所以：

### 1. 第 1 周周一是哪天（最重要）

填错的话所有日程都会整体偏移。判断依据：

- 看学校校历上「X 月 X 日 20XX 级本科生开课」那一行，那天就是第 1 周周一
- 交叉验证：如果校历写着 18 教学周 + 考试周，用「第 1 周周一 + 17 周」应该正好落在
  考试周前一周的周日

程序会检查你填的日期是不是周一，不是的话会提示。

### 2. 作息时间

界面里的下拉框列的是**当前版式自带的**预设。西工大版式带这三套：

| 预设 | 说明 |
|---|---|
| 西北工业大学 · 长安校区 | 1 节 08:30-09:15 … 13 节 20:40-21:25（每节 45 分钟） |
| 西北工业大学 · 友谊校区（冬季 10.1-4.30） | 每节 50 分钟，只有 1~12 节 |
| 西北工业大学 · 友谊校区（夏季 5.1-9.30） | 同上，下午与晚上整体后移 |

对不上就点「编辑节次时间…」手动改（改完若恰好与某套预设一致，下拉框会自动跳回那套
的名字，不会一直显示「自定义」）。如果某节课用到的节次没设时间，程序会明确报错
告诉你缺哪一节，而不是悄悄算错。

换成了别的版式而它没有自带作息（`inline-grid` / `flat-table` 就没有），程序会直接说
「还没有任何作息时间」并告诉你怎么填 —— 这一步必须人来定，代码不猜。

### 3. 相连节次要不要合并

教务系统排版时会把一门占用「11-13 节」的课拆成「11-12 节」和「13-13 节」两行。
界面里三档可选：

| 档位 | 效果 |
|---|---|
| **相连就合并**（默认） | 只要同一天、同一门课、同一教室且节次相连就合成一条。例如「1-2节 + 3-4节」= 08:30-12:10 |
| **只合并排版碎片** | 只合并「11-12节 + 13-13节」这种（其中一段是单节，明显是拆出来的），「1-2节 + 3-4节」视为两次课 |
| **不合并** | 完全按 PDF 的行 |

同一份课表，三档分别得到 18 / 22 / 26 个日程——**上课内容完全一样，只是日程条目数不同**。

### 4. 法定节假日与调休

界面里默认勾选「按法定节假日安排停课」，来源三选一（选哪个就**只用**哪个，避免
"以为在用联网数据、其实还在用内置预设"）：

| 来源 | 怎么用 | 适用 |
|---|---|---|
| **内置预设** | 默认。国务院 2026 年安排里与 2026 秋季学期相关的部分（中秋 09-25~27、国庆 10-01~07 停课；09-20、10-10 调休） | 就是 2026 秋 |
| **联网获取** | 界面「节假日数据 → 联网获取…」/ `--fetch-holidays`（年份留空就按「第 1 周周一 + 总周次」自动推该跨哪几个自然年） | 任意学期，含元旦等跨年假期 |
| **节假日文件** | 界面「选择文件…」/ `--holidays-file`（纯文本，格式见下） | 学校自己调课、或干脆不想联网 |

联网取到的是**缓存**的：内存 → 磁盘（`%LOCALAPPDATA%\TimetableToCalendar\holidays`）
→ 主源 → 备源，全失败才报错，并且会把"试了哪些地址、为什么失败、下一步怎么办"写清楚
（未来的年份会专门提示"国务院通知一般 11 月初才发布"）。想强制重取加 `--holidays-refresh`，
换内网镜像加 `--holidays-url 'https://…/{year}.json'`（支持 `file:///`）。

> 联网数据源是 [NateScarlet/holiday-cn](https://github.com/NateScarlet/holiday-cn)
> （按国务院办公厅通知整理，JSON 里带原文链接可溯源）。程序只在**你点「联网获取」时**
> 才出网，其它时刻一律离线；节假日数据本身不会自动更新。

**建议把联网结果落成文件再改**：`--fetch-holidays --save-holidays 节假日.txt`（界面里对应
「另存为节假日文件」）。学校自己的调课安排常与国务院口径不同，改这份文本比记着每次联网
更省事，以后用 `--holidays-file 节假日.txt` 指它即可。

调休日为什么通常不需要补课：高校通行做法是调休日照常执行「当天星期几」的课表，而不是去补
别的星期的课 —— 这种情况下那些课本就在循环日程里，程序**不会**再额外加一遍（真加了就会
出现同一时刻两条一模一样的课）。如果你的学校是"周六补周一的课"，把 `makeup_days` 里的条目
写成带 `follow_weekday`（0=周一 … 6=周日），或节假日文件里写 `调休 2027-04-25 周一`，
程序才会在那天补上对应星期的课。

放假不是把日程删掉，而是用 `EXDATE` 从循环里精确剔除那几天——日程数不变，但那几天不会
再有课、也不会再提醒。另外会在放假前一天晚上多发一条「明天放假」的提醒，并把当晚原定
要上的课列出来（标注已取消），避免那天晚上突然收不到提醒让人以为程序坏了。

## 解析结果一定要扫一眼

PDF 里的文字是「版面还原」出来的，绝大多数情况没问题，但有一条最容易出偏差：

- **教室和教师是靠空格分隔的**。如果某一行的教室名把教师「吃掉」了（例如教室显示成
  「实验大楼C座5楼某某某」），双击那一行改一下就行。

程序内置两个自检，解析完直接打在日志里：

- **时间冲突检测**：同一天同一时段不应该有两门不同的课。真实课表必然无冲突，
  所以一旦报冲突，几乎一定是解析串行了
- **解析失败条目**：某门课没解析出周次/节次时会明确列出来，不会静默丢掉

## 每个学期要手工更新两件事

| 要改的 | 在哪改 | 怎么确认 |
|---|---|---|
| **第 1 周周一** | 界面顶部「第 1 周周一」/ `--week1` | 看校历上「X月X日 20XX级本科生开课」那一行 |
| **本学期节假日安排** | 界面「节假日数据 → 联网获取…」/ `--fetch-holidays`（最省事），或「选择文件…」/ `--holidays-file` | 联网的就是当年国务院通知；再对照学校教务处调课通知 |

节假日文件是纯文本，格式很直白（界面里有「导出模板」按钮可以直接生成）：

```
放假 2027-04-04 2027-04-06 清明节
放假 2027-05-01 2027-05-05 劳动节
调休 2027-04-25
```

省略「执行星期几」= 那天照常执行当天星期几的课表；写成 `调休 2027-04-25 周一`
就是那天补周一的课。

### 程序会主动拦住「忘记更新」

内置的配置自检（`src/timetable/doctor.py`）专抓这类**不会报错、只会算错**的情况：

- 第 1 周周一不是周一 → 报错
- **填的日期推出来的学期和 PDF 里写的学期对不上** → 报错（专治「下学期忘了改日期」）
- **节假日预设全部落在本学期范围之外** → 报错（专治「沿用了上学期的节假日」）
- 课程用到的节次没设时间 → 报错（版式没自带作息时会直接说「还没有任何作息时间」）
- 自动识别出的版式**读不出教室**或仍有时间冲突 → 明确警告，不静默采用

报错时命令行会中止（退出码 3，加 `--force` 可强制生成），界面上会弹窗让你决定。

## 适用范围与已知限制

- **默认只保证西工大教务系统的《学生课表》版式**（七列表头 + 左侧节次栏 +
  「(N周)(N-M节) 教室 教师」）。其它学校靠**版式**适配：先试 `--auto-layout`，
  不像就照 `--dump-layout` 的输出写一份 JSON（见
  [换学校 / 换教务系统](#换学校--换教务系统版式)）。版式都不匹配时程序会
  **明确报错退出**（「没有找到星期一…星期日表头」或「没有解析到任何课程」），
  不会硬猜出一个错误结果。
- **`inline-grid` / `flat-table` 两个内置版式没有真实学校 PDF 验过**，只按常见教务导出
  格式实现并用合成 PDF 做了回归。它们更像"起步模板"而不是"某校开箱即用"。
- **单双周**：PDF 里的「2~4(双)周」会被正确展开成第 2、4 周。程序不是一个无限循环加例外，
  而是按连续区间拆成若干条日程，保证每条都能精确表达。
- **相连节次合并后是一条长日程**（例如周一 08:30-12:10），中间不会留出课间空档。
- **默认离线**：只有你点「联网获取…」/ 加 `--fetch-holidays` 时才出网取节假日，
  且取一次就缓存；除此之外不联网、不自动更新任何东西。
- **教室和教师靠空格分隔识别**，个别行可能识别错，用预览表改一次即可
  （`--dump-layout` 能直接看到每一行被切成了什么）。
- 自动识别版式是**猜**的：它会把每个版式的成绩打给你看，请务必扫一眼再用。

## 构建安装包

需要 Python 3 + PyInstaller，以及 Windows 自带的 `csc.exe`（.NET Framework 4）。
不依赖 Inno Setup / NSIS 之类的打包工具。

```powershell
pip install -r src\requirements.txt -r src\requirements-ocr.txt pyinstaller
powershell -ExecutionPolicy Bypass -File build_onedir.ps1             # → dist\TimetableToCalendar\
powershell -ExecutionPolicy Bypass -File build_installer.ps1 -Clean   # → dist\TimetableToCalendar-Setup.exe
```

原理：应用本体（PyInstaller onedir 目录）先用 **7-Zip 的 LZMA2** 压到约 1/3，再把
「压缩载荷 + 官方 `7za.exe` 解压内核 + 一个 8 KB 的小卸载器」内嵌进一个用 `csc.exe`
编译的 C# WinForms 程序里，所以最终只有一个 exe。

> `-Clean` 会在打包后删掉中间产物（应用本体目录和压缩载荷），只留安装包。

## 自检与测试

```powershell
pip install -r src\requirements-dev.txt

# 没有真实课表？先合成一份假的（个人课表不进仓库，但回归必须能跑）
python tools\make_fixture.py --check        # 生成 fixtures\nwpu-sample.pdf 并断言解析正确
python tools\make_fixture_alt.py --check    # inline-grid / flat-table 两种版式

python src\selftest.py  <你的课表.pdf>    # 端到端：解析 → 生成 → 用第三方库独立展开核对

python tools\test_holiday_fetch.py        # 联网节假日：合并/跨年/缓存/文本往返/错误分支
python tools\test_layout.py               # 版式层：切分策略、周次归一、JSON 校验、自动识别
python tools\test_timebased.py            # 「时刻制」课表：3位代码/时刻区间/教室教师粘连/反查
python tools\test_xlsx.py                 # Excel：模板往返、列名别名、导出→导入一致、错误定位
python tools\test_ocr.py                  # OCR：文字层判定、与坐标解析结果比对、低置信度外露
python tools\test_crosscheck.py           # OCR 交叉验证：假汉字检测、逐处比对、置信度门槛
python tools\resize_test.py               # 窗口缩放回归（含极小窗口）
python tools\resize_wm_test.py            # 窗口缩放回归（走窗口管理器，模拟拖边框）
python tools\table_fit_test.py <课表.pdf>  # 预览表列宽自适应（左右缩放不许裁掉右边的列）
python tools\check_corners.py             # 圆角控件边缘有没有暗角

# 安装包自检（不需要真的装一遍）
dist\TimetableToCalendar-Setup.exe --uitest ui.txt      # 控件清单 / 越界 / 重叠
dist\TimetableToCalendar-Setup.exe --pathcheck path.txt # 安装位置规范化规则（含幂等）
```

`selftest.py` 会做这几件事：

- 解析后检查「同一天同一时段是否出现两门不同的课」
- 对三种合并模式各生成一份 `.ics`，检查 CRLF、无超过 75 字节的行、标签配对
- **用 `recurring-ical-events` 独立展开所有循环日程**，把每晚那条汇总的内容与第二天
  实际展开出来的课程**逐条比对**（防止「提醒内容和实际课程对不上」）
- 检查同一天展开出的课程互不重叠（这条抓到了调休日重复排课的 bug，见 开发说明.md）
- 检查法定节假日当天确实没有课，且每个假期都有一条「明天放假」提醒
- 换学期场景：故意填错日期 / 沿用旧节假日，确认自检能报出对应错误

## 常见问题

**没有代码签名，SmartScreen 报警怎么办？**
正常现象。点「更多信息」→「仍要运行」。要对公分发需要买代码签名证书。

**安装位置能改吗？**
能。安装器会**自动在你选的位置下新建 `TimetableToCalendar` 子目录**
（选到 `D:\Tools` 就装到 `D:\Tools\TimetableToCalendar`），所以只选父目录就行；
卸载时如果那个父目录是安装时新建的、而且空了，会一并删掉，不留空文件夹。

**程序窗口能调整大小吗？**
能，横竖都能拖。默认约占屏幕四分之一；拉高时课程预览表跟着变高，压矮到装不下时
中间内容区出现滚动条，顶栏和底部按钮始终固定在窗口上。左右缩放时预览表的列宽会自动
压缩到各列下限，保证右边几列不会被裁掉。

**卸载后还有残留吗？**
没有。卸载器会把自己复制到 `%TEMP%` 再执行删除，所以安装目录不被任何进程占用，
目录能整个删掉。如果程序正在运行，卸载器会提示你先关掉它。

**换学期怎么用？**
只需改两处：第 1 周周一、本学期节假日。其余（周次换算、循环日程、提醒、合并）都与学期
无关。见上文「每个学期要手工更新两件事」。
